# LLM 自主判断集数功能 - SPEC 文档

## 1. 功能概述

本功能旨在让 LLM 根据输入小说内容自主判断最佳集数（范围：60-100集），并生成对应集数的短剧剧本。

### 1.1 核心目标
- 输入：小说文本
- 输出：符合格式规范的短剧剧本（60-100集）
- 集数决策：由 LLM 根据小说内容复杂度、情节发展、人物关系等因素自主决定

### 1.2 设计原则
- **智能决策**：LLM 根据小说内容自主判断集数
- **范围约束**：集数必须在 60-100 集范围内
- **均衡分配**：每集内容量均衡，避免某集过长或过短
- **剧情完整**：确保小说核心情节完整呈现

---

## 2. 功能需求

### 2.1 集数决策逻辑
1. LLM 首先分析小说内容，评估：
   - 故事主线数量
   - 人物关系复杂度
   - 情节转折点数量
   - 总字数与信息量
2. 根据评估结果，在 60-100 集范围内选择最佳集数
3. 输出集数决策依据（可选）

### 2.2 剧本生成要求
1. 严格遵循原有的剧本格式规范
2. 每集时长建议：2-5分钟（约300-800字/集）
3. 每集包含：
   - 集标题
   - 1-3个场景
   - 明确的剧情推进点
   - 适当的悬念/卡点

### 2.3 字数约束
- 每集内容字数：300-800 字（中文）
- 总剧本字数：约 18,000 - 80,000 字
- 字数统计方式：基于 Unicode 字符数（去除空白字符）

## 3. 提示词设计

### 3.1 系统提示词

```
你是一位经验丰富的短剧剧本创作总监，擅长将长篇小说改编为精彩的网络短剧。

## 核心任务
1. **集数规划**：根据小说内容复杂度，在60-100集范围内自主决定最佳集数
2. **剧本创作**：将小说改编为符合规范的短剧剧本

## 集数决策指南
- 60-70集：适合情节紧凑、主线清晰的故事
- 71-85集：适合中等复杂度、多支线故事
- 86-100集：适合宏大叙事、多人物、多反转的故事

## 剧本格式规范
1. 集数标注："第X集"或"第一集"开头
2. 场景格式："1-1 日 内 九重天"（编号-子编号 日/夜 内/外 地点）
3. 动作描述：使用 △ 符号开头标注除对话外的内容
4. 语气神态：使用 () 括号描写人物说话时的语气、神态、动作
5. 内心独白：使用 VO 或 OS 标记
6. 回忆镜头：开始用【闪回】，结束用【闪出】

## 内容要求
- 每集字数控制在300-800字
- 每集包含1-3个场景
- 每集结尾设置悬念或卡点
- 保持剧情连贯性和节奏感

## 输出格式
1. 首先输出集数决策：【集数：XX集】
2. 然后输出完整的剧本内容

请直接输出剧本内容，不要有额外解释。
```

## 5. 字数验证机制

### 5.1 验证逻辑

```python
def validate_episode_lengths(script_content: str, min_chars: int = 300, max_chars: int = 800) -> tuple[bool, list[str]]:
    """
    验证每集字数是否符合要求
    
    Args:
        script_content: 剧本内容
        min_chars: 每集最小字数
        max_chars: 每集最大字数
        
    Returns:
        (is_valid, issues) 元组
    """
```

### 5.2 验证规则

1. 按集分割剧本内容
2. 统计每集的有效字符数（去除空白和换行）
3. 检查是否在 300-800 字范围内
4. 输出不符合要求的集数列表

## 7. 错误处理

| 错误类型 | 描述 | 处理方式 |
|----------|------|----------|
| `InvalidEpisodeCountError` | 集数不在60-100范围内 | 重新生成或提示用户 |
| `EpisodeLengthError` | 单集字数超出范围 | 标记问题集数，提示优化 |
| `ContentOverflowError` | 内容不足以支撑最小集数 | 提示用户或减少集数 |

## 8. 性能考虑

### 8.1 分批生成策略

对于超长剧本（80集以上），考虑分批生成：
- 每批生成 20-30 集
- 保持上下文连贯性
- 避免单次生成超时

### 8.2 缓存机制

- 缓存集数决策结果
- 缓存已生成的剧本片段
- 支持断点续生成
